# Annihilation Masters — регламент как страница

Регламент турнира живёт как обычная веб-страница: читается сверху вниз, без
разбивки на листы A4. Организаторы правят его прямо на сайте — с планшета
тоже, — и изменения сразу видят все.

```
index.html        публичная страница (читает content.json)
admin.html        редактор (вход по паролю)
setup.html        разовый мастер настройки публикации (см. «Хостинг»)
content.json      сам регламент: разделы и блоки
assets/
  am-web.css      оформление страницы (веб-версия печатной системы)
  admin.css       оформление редактора
  render.js       рендерер блоков — один и тот же для страницы и редактора
  page.js         логика страницы
  admin.js        логика редактора
  store.js        куда сохранять: локальный сервер или GitHub API
  setup.js        сборка lock-файла для статического хостинга
  art/hero.jpg    арт шапки
  uploads/        картинки, загруженные через редактор
server.py         локальный сервер: статика + API + пароль
history/          снимки предыдущих версий (создаётся при сохранении)
```

## Что умеет редактор

- Править любой текст прямо в макете. **Enter** в абзаце создаёт следующий абзац,
  в списке — следующий пункт; Shift+Enter просто завершает правку.
- **«＋» в полоске блока** — пустой абзац сразу под этим блоком, курсор уже внутри.
  Другой тип — «⋯» → «Вставить блок ниже»; «＋ Блок» внизу раздела добавляет в конец.
- **Оглавление**: «⋯» в панели → «Перейти к разделу» — список разделов, тап
  прокручивает к нужному и подсвечивает его.
- Блоки: абзац, подзаголовок, пункты, врезка, таблица, параметры, условия, этапы,
  призовые, вопросы, ссылки, **картинка**.
- Картинки — загрузка с устройства (png/jpg/webp/gif до 8 МБ) прямо в редакторе;
  уже загруженные лежат в списке с размерами и вставляются одним касанием.
  Блок с картинкой сразу открывает выбор файла — не нужно искать кнопку.
  Шапка страницы тоже меняет картинку через выбор, а не через путь к файлу.
- **Картинка не растягивается** шире своих пикселей: размер пишется в документ
  (`width`/`height`), поэтому мыла не будет даже на большом экране, а вёрстка
  не прыгает при загрузке. Мелкий кадр редактор отмечает словом «мелко».
  Для баннера шапки нужно от 2400 px по ширине — иначе на экранах с ретиной
  картинка растягивается в 2 раза.
- Шапка настраивается целиком: надзаголовок, название, лид, сезон, формат, косты,
  редакция, арт, примечание в подвале и **строки под названием** — свои пары
  «подпись → значение» вместо стандартных.
- У блока «⋯»: дублировать, превратить в другой тип (текст переносится),
  перенести в другой раздел, вставить блок ниже, задать размер картинки, удалить.
- **История версий**: каждая публикация сохраняет предыдущую (до 40). «В редактор»
  открывает снимок для правки, «Вернуть» сразу откатывает живую страницу.
- Отмена шагов: `↶`/`↷` в левом нижнем углу, до 40 шагов, Ctrl+Z / Ctrl+Shift+Z.
- «Начать текст заново» в «Шапке» — очищает разделы, оставляя шапку.
- Черновик живёт в браузере; «Просмотр» показывает его, не публикуя.
- **Ничего не вылезает**: длинные слова и адреса переносятся, таблицы
  прокручиваются внутри себя, половинные картинки на телефоне становятся во всю
  ширину, пустой блок всегда можно коснуться — у него есть подсказка.

## Запуск

```bash
python server.py
```

Первый запуск создаёт пароль админки и печатает его в консоль. Дальше:

- страница — http://127.0.0.1:8080/
- редактор — http://127.0.0.1:8080/admin.html
- планшет — тот же адрес, но с IP машины (`http://192.168.x.x:8080/admin.html`),
  устройство должно быть в той же сети Wi-Fi.

Полезное:

```bash
python server.py --port 8123        другой порт (8080 занят локальным llama-сервером)
python server.py --set-password     сменить пароль
python server.py --host 127.0.0.1   только с этой машины, без планшета
```

Если Windows спросит про доступ в сеть — разрешить для частных сетей, иначе
планшет не подключится. Файл `server.config.json` хранит только хэш пароля;
его, как и `history/`, в публичный репозиторий класть не нужно.

## Как править

1. Открыть `admin.html`, ввести пароль.
2. Коснуться любого текста — он редактируется прямо в макете. Enter завершает
   правку пункта, абзац переносится по Enter.
3. Структура: у каждого блока кнопки `↑ ↓ ⋯`, у раздела — те же плюс «＋ Блок».
   Перестановка кнопками, а не перетаскиванием: на планшете так надёжнее.
4. `⋯` у блока — дублировать, превратить в другой тип, перенести в другой раздел,
   добавить пункт/строку/колонку, сменить тон врезки, задать размер картинки,
   удалить. `⋯` у раздела — добавить блок, дублировать, удалить раздел.
5. «Опубликовать» — запись уходит на сервер, страница обновляется для всех.
   До публикации всё живёт в черновике браузера; «Просмотр» открывает этот
   черновик в новой вкладке.
6. Кнопка `⋯` в панели — «Шапка страницы», «Картинки», «История версий»,
   «Подсказки», «Выйти».
7. «Шапка» — название, лид, сезон, формат, косты, редакция, картинка шапки,
   примечание в подвале, строки под названием (свои пары «подпись → значение»).
   Там же выгрузка и загрузка JSON.
8. Картинки: блок «Картинка» → «Заменить картинку» → «Загрузить с устройства».
   Файл ложится в `assets/uploads/`, путь вставляется сам. Уже загруженные видны
   списком и вставляются одним касанием.
9. «История версий» хранит до 40 прошлых публикаций: «В редактор» открывает
   снимок, «Вернуть» сразу откатывает живую страницу (откат тоже обратим).
10. Ошиблись — в левом нижнем углу `↶` и `↷` (до 40 шагов; на клавиатуре
    Ctrl+Z / Ctrl+Shift+Z). «Начать текст заново» в панели «Шапка» очищает все
    разделы, оставляя шапку: удобно, когда регламент переписывается целиком.
    Отменить очистку можно тем же `↶`.

### Разметка в текстах

`**жирный**`, `*курсив*`, `[текст](https://ссылка)` и голые ссылки — работают в
абзацах, врезках, пунктах и примечании. В редакторе видно звёздочками, на
странице — уже оформленным.

### Блоки

| Тип | Что это |
|---|---|
| Абзац | обычный текст |
| Подзаголовок | мелкий капс внутри раздела |
| Пункты | нумерованный список, номера считаются сами (`4.1`, `4.2`) |
| Врезка | замечание на линии; тон: обычная / важная / запрет |
| Таблица | строки и колонки, только линии |
| Параметры | пара «параметр → значение» |
| Условия | перечисление через волосяные линии |
| Этапы | таймлайн с шагами |
| Призовые | места и суммы |
| Вопросы | вопрос → ответ |
| Ссылки | список ссылок с адресами |
| Картинка | файл с подписью; ширина: во всю, поуже, половина |

Картинки кладутся в `assets/uploads/` (имя собирается из даты и имени файла,
кириллица транслитерируется). В публичном репозитории они едут вместе с сайтом —
это часть регламента, их не нужно никуда выгружать отдельно.

## Хостинг

Сайт статический: `index.html` + `assets/` + `content.json`. Вопрос только в
том, куда редактор пишет изменения — под это в `assets/store.js` два режима.

### Режим 1 — любой хостинг с Python (пароль проверяется на сервере)

VPS, PythonAnywhere, домашний сервер: перенести папку, поставить пароль,
запустить `python server.py`. Ничего менять не нужно. Проверено.

### Режим 2 — GitHub Pages и подобное (без бэкенда)

Страница работает сразу, а сохранение идёт коммитом через API GitHub по токену.
Токен лежит в `admin.lock.json` **зашифрованным вашим паролем** (AES-GCM, ключ из
PBKDF2), поэтому файл можно держать в публичном репозитории: без пароля он
бесполезен. Пароль остаётся единственным секретом.

Порядок с нуля:

1. Создайте **публичный** репозиторий (имя любое, например `am-reglament`).
2. Загрузите в него содержимое папки `site/`: `index.html`, `admin.html`,
   `setup.html`, `content.json`, `assets/`. Файлы `server.py`, `server.config.json`,
   `history/` и тестовые обвязки публиковать не нужно — они в `.gitignore`.
3. `Settings → Pages → Source: Deploy from a branch`, ветка `main`, папка `/ (root)`.
4. Откройте `https://<логин>.github.io/<репозиторий>/` — страница уже живая.
5. Откройте там же `setup.html`, заполните логин, репозиторий, ветку, токен
   (fine-grained, право **Contents: Read and write**, только на этот репозиторий)
   и пароль редактора. Скачайте `site-config.json` и `admin.lock.json`,
   положите их в корень репозитория.
6. Через минуту `/admin.html` спрашивает этот пароль, «Опубликовать» создаёт коммит.

Что в этом режиме иначе, чем на своём сервере:

- **Картинки** загружаются тоже коммитом (`assets/uploads/<дата>-<имя>.png`), каждая
  загрузка — отдельный коммит. Список «уже загруженные» читается из репозитория.
  Размер кадра редактор меряет сам в браузере, поэтому картинка не растягивается.
- **История версий** — это история коммитов GitHub: откат делается `Revert` в
  репозитории, своей ленты снимков в этом режиме нет (редактор так и пишет).
- **Пароль** здесь шифрует токен, а не защищает сервер: кто получил
  `admin.lock.json` и пароль, тот может писать в репозиторий.

Проверено: на локальном моке API — 13 проверок (вход по зашифрованному
lock-файлу, список картинок, загрузка коммитом, измерение кадра, удаление,
публикация с 11 разделами, неверный пароль, сообщение про историю); на **живом**
GitHub — расшифровка lock-файла в браузере, чтение `content.json` по API и запись
файла коммитом (право `Contents: read and write` подтверждено).

Действующий репозиторий проекта: <https://github.com/wpBSsky/am-reglament>.
Пароль редактора — `annihilation-2026`, он же пароль локального сервера.
Токен живёт только внутри `admin.lock.json` (AES-GCM) и в открытом виде не
встречается ни в одном файле; срок токена — 90 дней, отзывается в GitHub одной
кнопкой.

## API сервера

| Метод | Что делает |
|---|---|
| `GET /api/ping` | жив ли сервер |
| `POST /api/auth` | проверка пароля |
| `GET /api/content` | текущий документ |
| `PUT /api/content` | сохранить (заголовок `X-AM-Pass`) |
| `POST /api/upload` | загрузить картинку (`X-AM-Pass`, `X-File-Name`) |
| `GET /api/uploads` | список картинок |
| `DELETE /api/uploads?name=…` | удалить картинку |
| `GET /api/history` | список версий |
| `GET /api/history/<файл>` | версия целиком |
| `POST /api/restore` | вернуть версию в публикацию |

Тип картинки проверяется по содержимому (png/jpg/webp/gif), не по расширению;
лимит — 8 МБ. Файлы с картинками и `history/` лежат рядом и в git не нужны
(кроме `assets/uploads/` — это часть сайта).

Для публичного репозитория в git не нужны `server.py`, `server.config.json`,
`history/` — см. `.gitignore`.
